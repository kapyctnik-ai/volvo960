# Volvo 960 Actuators

Android-приложение для ручного управления актуаторами Volvo 960 (1996, ISO 9141-2)
через дешёвый Bluetooth-адаптер ELM327 v1.4b (Bluetooth Classic / SPP).

## Статус

Первая полная сборка архитектуры (транспорт, реестр, hold-repeat, UI) реализована
целиком за один заход, без реального железа и без Android SDK в среде разработки —
**сборка (`./gradlew assembleDebug`) и запуск на устройстве ещё не проверялись**.
Перед первым выездом к машине обязательно соберите и прогоните приложение хотя бы
на телефоне без адаптера (экран консоли покажет "нет соединения" — это ожидаемо).

## Архитектура

```
transport/   Elm327Transport — Bluetooth-сокет, единая mutex-очередь команд,
             автопереподключение, ConnectionState как StateFlow.
             НЕ трогать при добавлении новых актуаторов.

data/        Actuator (Room-сущность) — реестр актуаторов. Новый узел машины =
             новая запись в БД, не новый код.

service/     HoldManager — параллельные hold-repeat циклы поверх общей очереди
             транспорта; глобальный watchdog 30 с без ответа.
             HoldService — foreground-сервис, WAKE_LOCK, уведомление со списком
             активных удержаний и кнопками "стоп" на каждое.

ui/main/     Главный экран: статус подключения, активные удержания, реестр.
ui/console/  Консоль сырых команд — инструмент подбора новых актуаторов,
             логирует весь трафик в файл, "Сохранить как актуатор".
ui/editor/   Форма создания/редактирования записи реестра.
```

`VolvoApp` (Application) держит все синглтоны (`transport`, `holdManager`,
`repository`, `notificationHelper`) — они переживают отдельные Activity и продолжают
работать в фоне даже без открытого экрана.

## Протокол вентилятора (расшифровано)

Управление актуаторами идёт не по стандартному OBD-II, а по собственному
протоколу Volvo **KWP D3B0** поверх K-line, ECU `7A` (Motronic M4.4).
Последовательность снята с рабочего сеанса 850 OBD-II через btsnoop и
зашита в карточку «Вентилятор радиатора».

```
ATL1 / ATS1 / ATH1 / ATAL / ATE0   формат вывода
ATSP 3                             ISO 9141-2
ATKW0                              не проверять keyword
ATSR 13                            адрес тестера 13
ATAT 1 / ATST 32                   тайминги
ATIIA 7A                           init-адрес = ECU 7A (Motronic)
ATWM 82 7A 13 A1                   keep-alive сессии (сервис A1)
ATSI                               5-baud slow init -> BUS INIT: ...OK
ATKW                               -> 1:D3 2:B0
ATSH 85 7A 13                      заголовок: формат 85, ECU 7A, тестер 13
B00E 3203                          включение вентилятора
                                   -> 83 13 7A F0 0E 0E
ATSH 82 7A 13
A0                                 конец сессии -> 82 13 7A E0 EF
ATPC
```

`F0` = `B0 + 0x40`, то есть положительный ответ ECU по правилам KWP.

Кадр имеет вид `B0 <id> 32 03`, ответ ECU — `83 13 7A F0 <id> <id>`:

| Узел | Кадр | Ответ |
|---|---|---|
| Вентилятор, малая скорость | `B00E 3203` | `83 13 7A F0 0E 0E` |
| Вентилятор, большая скорость | `B01F 3203` | `83 13 7A F0 1F 1F` |

**Кадр переключает выход, а не устанавливает его.** Повтор кадра на
интервале включал вентилятор и тут же гасил его обратно. Поэтому в карточке
кадр стоит последней строкой init-скрипта (уходит один раз), повторяемая
команда — безобидный `ATRV` (держит удержание живым, не трогая K-line),
а команда выключения — тот же кадр ещё раз плюс закрытие сессии.

**ECU защёлкивает выход.** Вентилятор продолжает крутиться с вынутым ключом,
пока не придёт обратное переключение. Если приложение убить принудительно,
команда выключения не уйдёт и узел останется включённым.

Опрос температуры ОЖ автоматически ставится на паузу на время удержания:
обычный запрос OBD-II, посланный внутрь фирменной сессии, её порвёт.

## Как снять байты другого актуатора (тем же способом)

Управление актуаторами у Volvo идёт не по стандартному OBD-II, а по
собственному протоколу **KWP D3B0** поверх K-line, ECU `7A` (Motronic 4.4).
Готовых публичных байт-таблиц для теста вентилятора нет. Зато байты можно
снять с приложения, которое на этой машине уже работает (например
«850 OBD-II», у него есть Coolant Fan Test для ECM Motronic).

**Способ 1 — прямо в приложении (30 секунд).** В диалоге Coolant Fan Test
под тумблерами есть две строки (`XXX.`). Включи тумблер и посмотри, не
появятся ли там отправленный запрос и ответ. Если да — это и есть нужный hex.

**Способ 2 — btsnoop-лог Bluetooth (надёжно, без root).**

1. Настройки → Для разработчиков → включить **«Журнал HCI Bluetooth»**
   (Enable Bluetooth HCI snoop log).
2. Выключить/включить Bluetooth, чтобы лог начал писаться.
3. Открыть 850 OBD-II → подключиться → ECM Motronic → Coolant Fan Test →
   включить тумблер, подержать, выключить. Ничего лишнего не жать.
4. Забрать лог. Обычно `/sdcard/MIUI/debug_log/common/btsnoop_hci.log`,
   либо через Настройки → Для разработчиков → «Отчёт об ошибке», внутри
   архива лежит `btsnoop_hci.log`.
5. Трафик SPP идёт открытым текстом — команды ELM327 видно как ASCII.
   Быстро глянуть можно так:

   ```
   strings btsnoop_hci.log | grep -Ei '^(AT|[0-9A-F]{4,})'
   ```

   Либо открыть лог в Wireshark, фильтр `btspp`.
6. Скопировать команды, что ушли при включении вентилятора, в карточку
   актуатора: настройка адаптера → в поле «Init-скрипт», сама команда
   включения → в поле «Команда включения». Команду выключения — в
   «Команда выключения».

Карточка «Вентилятор радиатора (M4.4)» уже создана в реестре с готовым
init-скриптом; остаётся вставить байты команды.

## Как подобрать новый актуатор

1. Подключитесь к адаптеру на главном экране (адаптер должен быть уже
   сопряжён в настройках Bluetooth Android — сканирование в самом приложении
   не делается).
2. Откройте «Консоль команд», пробуйте байты вручную.
3. Как только команда сработала — «Сохранить как актуатор», укажите имя и
   тип поведения (разово / удержание).
4. На главном экране появится карточка с тогглом (удержание) или кнопкой
   (разово).

## Сборка

Нужен Android SDK (compileSdk 34) и подключение к `google()`/`mavenCentral()` —
в среде, где писался код, доступа к `dl.google.com` не было, поэтому
`./gradlew assembleDebug` тут не запускался. Обёртка Gradle (8.7) уже
сгенерирована и закоммичена.

```
./gradlew assembleDebug
```

minSdk 26 (Android 8), стек: Kotlin, Room (KSP), coroutines, обычные Android
Views + ViewBinding, минимум зависимостей.
