# Туннель Сервер А → Сервер Б (обычный WireGuard)

## Что получается

```
ноут ──AmneziaWG──▶ Сервер А ──WireGuard──▶ Сервер Б ──▶ интернет
                    136.244.106.70          139.84.177.77
```

Внешний IP на ноуте = IP сервера Б. Сервер Б напрямую с ноута не нужен —
всё общение с ним идёт с сервера А.

Адресация линка А↔Б: `10.66.66.0/30`, Б = `.1`, А = `.2`.
Порт туннеля на Б: UDP 51820. Интерфейс на А: `wgb` (существующий
AmneziaWG-интерфейс не трогается).

## Установка

Один скрипт, запускается **на сервере А** от root. Он сам зайдёт по ssh
на Б и настроит его — пароль Б спросит один раз.

```bash
ssh root@136.244.106.70
curl -fsSLO https://raw.githubusercontent.com/kapyctnik-ai/volvo960/claude/wireguard-tunnel-setup-lfiirs/scripts/wg-a2b/setup.sh
SERVER_B_IP=139.84.177.77 bash setup.sh
```

Если файл проще скопировать руками — просто перенеси `scripts/wg-a2b/setup.sh`
на сервер А любым способом и запусти так же.

Подсеть клиентов AmneziaWG скрипт определяет сам из конфига
(`/etc/amnezia/amneziawg/*.conf`, `/etc/wireguard/*.conf`). Если не нашёл —
задай явно:

```bash
SERVER_B_IP=139.84.177.77 AWG_SUBNET=10.8.1.0/24 bash setup.sh
```

## Что скрипт делает

**На сервере Б** (`/etc/wireguard/wg0.conf`):
* поднимает wg0 `10.66.66.1/30`, слушает UDP 51820;
* `net.ipv4.ip_forward=1`;
* MASQUERADE для `10.66.66.0/30` наружу + FORWARD-разрешения;
* открывает 51820/udp в ufw/firewalld/iptables;
* `systemctl enable wg-quick@wg0`.

**На сервере А** (`/etc/wireguard/wgb.conf`):
* поднимает wgb `10.66.66.2/30`, peer = Б, `AllowedIPs = 0.0.0.0/0`,
  `PersistentKeepalive = 25`;
* **`Table = off`** — wg-quick не трогает основную таблицу маршрутов,
  поэтому свой ssh и весь собственный трафик сервера А идут как шли,
  через его родной аплинк. Это главное отличие от «просто wg-quick
  с 0.0.0.0/0», который бы отрезал ssh;
* вместо этого policy routing: `default dev wgb` в таблице 200 и правило
  `from <подсеть AmneziaWG> lookup 200`. То есть в Б уходит **только**
  трафик клиентов;
* MASQUERADE на выходе в wgb (Б видит один адрес 10.66.66.2 — на Б не надо
  ничего знать про подсеть клиентов);
* MSS clamping и `MTU = 1380`, чтобы не рвались крупные TCP-пакеты
  из-за двойной инкапсуляции;
* `systemctl enable wg-quick@wgb` — переживает ребут.

Правило MASQUERADE существующего AmneziaWG-конфига (`-o eth0`) не мешает:
исходящий интерфейс у клиентского трафика теперь другой.

## Проверка

На сервере А:

```bash
wg show wgb                                   # должен быть свежий handshake
ping -c2 -I wgb 10.66.66.1                    # линк до Б
curl --interface wgb https://api.ipify.org    # должно вернуть 139.84.177.77
ip rule show                                  # from 10.8.x.0/24 lookup 200
```

С ноута (подключённого к AmneziaWG): любой «какой у меня IP» должен
показать **139.84.177.77**.

## Тонкости

* **DNS.** Если в конфиге AmneziaWG-клиента `DNS = 8.8.8.8` (или другой
  внешний), запросы пойдут через Б — утечки нет. Если DNS указывает на
  сам сервер А, резолвинг будет уходить наружу с IP сервера А. Для полной
  чистоты ставь клиентам публичный DNS.
* **MTU.** Если где-то тормозит или не грузятся тяжёлые страницы —
  опусти MTU у клиентов AmneziaWG до 1280 и/или `MTU` в `wgb.conf` до 1320.
* **Ребут.** Обе стороны в `systemd` (`wg-quick@wg0` на Б,
  `wg-quick@wgb` на А), поднимаются сами.
* **Откат.** На сервере А: `bash scripts/wg-a2b/rollback.sh` — снимает wgb
  и правила, клиенты снова выходят через IP сервера А.
* **Ключи** генерируются на сервере А при установке и лежат в
  `/etc/wireguard/*.conf` с правами 600. В репозиторий не попадают.
